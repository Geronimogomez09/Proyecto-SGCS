Metodologías Ágiles

Son formas de organizar el desarrollo de software que buscan entregar valor rápidamente, adaptarse a los cambios y mantener una comunicación constante con el cliente y el equipo.

Metodología XP

Extreme Programming

XP se enfoca principalmente en la calidad del código y la adaptación rápida a los cambios.

En XP no hay un conjunto de roles tan rígido como en Scrum. Pero sí se pueden separar en cargos aunque no sean tan independientes.

Programadores

Escriben y mejoran el código. Trabajan en parejas y realizan pruebas.

Cliente

Define qué necesita el sistema, prioriza las funcionalidades y da su opinión sobre lo desarrollado.

Tester

Ayuda a crear y ejecutar pruebas para comprobar que el software funciona correctamente.

Coach

Guía al equipo para que siga correctamente las prácticas de XP y ayuda a resolver problemas del proceso.

12 principios

La idea es entregar partes del software desde temprano, en lugar de esperar hasta el final del proyecto. Así, el cliente puede ver los avances, probarlos y dar su opinión.

Los cambios son normales durante un proyecto. Si el cliente necesita modificar algo, el equipo debe poder adaptarse aunque el desarrollo ya esté avanzado.

Se busca entregar versiones que realmente funcionen de manera regular. De esta forma, el cliente puede probar el producto y detectar problemas antes de que el proyecto termine.

El cliente y el equipo de desarrollo deben mantenerse en contacto durante todo el proyecto. Esto ayuda a entender mejor lo que se necesita y evita hacer un producto diferente al esperado.

El equipo debe estar formado por personas comprometidas y motivadas. Se les debe dar confianza, herramientas y un ambiente adecuado para que puedan realizar bien su trabajo.

La comunicación cara a cara o directa permite resolver dudas y problemas más rápidamente. Es más fácil entenderse hablando directamente que mediante mensajes o documentos demasiado extensos.

El avance del proyecto se mide principalmente por las funciones que ya están funcionando. No alcanza con tener documentos o diseños; lo importante es que el software pueda utilizarse.

El equipo debe trabajar a un ritmo que pueda mantener durante todo el proyecto. Se deben evitar jornadas excesivas y el agotamiento, porque pueden afectar la calidad del software.

No solo importa que el programa funcione, también debe estar bien desarrollado. Un buen diseño y código de calidad facilitan las futuras modificaciones y reducen los problemas.

Se debe hacer solo lo necesario, evitando agregar funciones o elementos que no aporten valor. Un sistema más simple suele ser más fácil de entender, mantener y modificar.

El equipo tiene cierta libertad para organizar su trabajo y decidir cómo realizar las tareas. Esto permite que quienes conocen el proyecto puedan tomar decisiones y encontrar mejores formas de resolver los problemas.

Al finalizar cada etapa, el equipo analiza qué salió bien y qué podría hacerse mejor. Con esa información, puede cambiar su forma de trabajar para mejorar continuamente en los siguientes ciclos.
