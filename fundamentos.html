CALIDAD DE SOFTWARE

Te interesa Calidad de Software

La calidad de software busca garantizar que un sistema sea confiable, eficiente y cumpla con las necesidades de sus usuarios.
Conocé sus fundamentos, técnicas de aseguramiento, pruebas y herramientas utilizadas para desarrollar software de calidad.

01

Fundamentos de Calidad

La calidad permite comprobar que un sistema cumple con lo esperado y satisface las necesidades de sus usuarios.

La calidad del software se refiere al grado en que un sistema cumple con los requisitos establecidos y satisface las necesidades de sus usuarios.

No solo implica que el programa funcione correctamente, sino también que sea seguro, eficiente, fácil de usar y mantener.

02

Conceptos claves de Calidad

Algunos conceptos fundamentales para comprender cómo se analiza la calidad de un software.

Calidad

Grado en que un software cumple requisitos y expectativas.

Requisitos

Característica o función que el sistema debe cumplir.

Defectos

Error o problema que puede provocar un comportamiento incorrecto.

Procesos

Actividades utilizadas para desarrollar y mantener el software.

Métricas

Medidas utilizadas para evaluar características del software o del proceso.

Indicadores

Información obtenida a partir de métricas para analizar el estado de la calidad.

Evaluación

Proceso de medir y analizar si el software cumple determinados criterios.

Mejora continua

Búsqueda constante de mejoras en los productos y procesos.

05

¿Técnicas de aseguramiento de la calidad del software?

Las técnicas de aseguramiento de calidad de software permiten detectar errores, prevenir problemas y asegurar que el producto cumpla con los requisitos establecidos.
Para eso tenemos los niveles de prueba, que indican dónde se prueba, y los tipos de prueba, que muestran cómo se prueba.

NIVELES DE PRUEBA

Niveles de pruebas

Se realizan en diferentes etapas del desarrollo para validar cada parte del sistema.

Característica Unitarias Integración Sistema
¿Qué son? Verifican el funcionamiento de la unidad de código más pequeña de forma aislada. Comprueban cómo interactúan entre sí diferentes módulos, componentes o servicios. Evalúan el software completo e integrado frente a los requisitos establecidos.
¿Qué se prueba? Funciones, métodos, clases o módulos. Interfaces entre módulos, paso de datos y comunicación entre componentes. Funcionalidad total, rendimiento, usabilidad y seguridad.
Ejemplos Frameworks de pruebas, verificación de lógica y resultados esperados. Pruebas de API, pruebas de servicios, stubs y mocks. Pruebas end-to-end, pruebas de carga y pruebas de aceptación.
TIPOS DE PRUEBA

Tipos de pruebas

Se clasifican según el conocimiento que se tiene del funcionamiento interno del sistema.

¿Cuál es la diferencia?

La caja negra se concentra en el comportamiento observable del software, mientras que la caja blanca analiza su estructura y lógica interna.
