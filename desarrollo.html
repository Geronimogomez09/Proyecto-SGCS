¿Porque es importante el desarrollo de software ?

CICLO DE VIDA MODELOS RESUMEN
01

Ciclo de vida de un software

El ciclo de vida de un software es el conjunto de procesos que se siguen para desarrollarlo y mantenerlo.

Análisis

Se identifican las necesidades del usuario y se define qué debe hacer el sistema.

Diseño

Se define cómo será el sistema, su estructura, interfaz y funcionamiento.

Desarrollo

Se programa el sistema siguiendo lo definido en las etapas anteriores.

Pruebas

Se verifica que el sistema funcione correctamente y se buscan errores.

Despliegue

El sistema se instala y se pone a disposición de los usuarios.

Mantenimiento

Se realizan correcciones, mejoras y actualizaciones del sistema.

02

Modelos tradicionales del desarrollo de software

Los modelos tradicionales son diferentes formas de organizar y planificar las etapas del desarrollo de software. Entre los principales se encuentran el modelo en Cascada, el modelo en V y los modelos Iterativos e Incrementales.

MODELO 01

Modelo en Cascada

Organiza el desarrollo en etapas secuenciales. Generalmente, una fase se completa antes de comenzar la siguiente.

Ventajas

  • Es simple y fácil de entender.
  • Sus etapas y objetivos están bien definidos.
  • Facilita la planificación y documentación.
  • Es útil cuando los requisitos son claros y estables.

Desventajas

  • Es difícil volver atrás para modificar una etapa.
  • Los cambios pueden resultar costosos.
  • El usuario observa el producto principalmente al final.
  • No se adapta bien a requisitos cambiantes.

¿Cuándo utilizarlo?

Puede utilizarse cuando los requisitos están claramente definidos, existe poca probabilidad de cambios y se necesita una planificación y documentación detalladas.

Ventajas

  • Relaciona las actividades de desarrollo con las pruebas.
  • Permite planificar las pruebas desde etapas tempranas.
  • Facilita la documentación y el seguimiento.
  • Es útil cuando se requieren procesos controlados.

Desventajas

  • Los cambios tardíos pueden ser difíciles de gestionar.
  • Requiere una planificación detallada.
  • Puede resultar rígido frente a requisitos cambiantes.
  • No está pensado para modificaciones constantes.

¿Cuándo utilizarlo?

Es útil en proyectos donde la verificación y validación son especialmente importantes y los requisitos pueden definirse desde el comienzo.

MODELO 03

Modelos Iterativos e Incrementales

El desarrollo se divide en ciclos o iteraciones, donde el sistema evoluciona mediante pequeñas entregas que incorporan nuevas funcionalidades.

02 Desarrollo
03 Pruebas

¿Cómo funciona?

Cada iteración produce una versión funcional del sistema. Los incrementos posteriores agregan nuevas funciones o mejoras, permitiendo obtener resultados de manera progresiva.

Ventajas

  • Permite obtener resultados funcionales antes de finalizar el proyecto.
  • Facilita incorporar cambios y nuevas necesidades.
  • Permite recibir retroalimentación durante el desarrollo.
  • Los riesgos pueden detectarse de forma progresiva.

Desventajas

  • Requiere una buena organización de las iteraciones.
  • Puede aumentar la complejidad de la planificación.
  • Las modificaciones frecuentes deben gestionarse correctamente.
  • El sistema necesita una arquitectura que permita crecer progresivamente.

¿Cuándo utilizarlo?

Puede utilizarse cuando se espera obtener versiones progresivas del producto, recibir retroalimentación durante el desarrollo o incorporar nuevas funcionalidades de forma gradual.

COMPARACIÓN

¿Cómo se diferencian?

Cascada

Avanza de forma secuencial y ordenada entre sus etapas.

Modelo en V

Relaciona cada etapa de desarrollo con una etapa de pruebas.

Iterativo e Incremental

Construye el sistema progresivamente mediante ciclos y entregas.
