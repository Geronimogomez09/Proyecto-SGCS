Elegí una letra para filtrar

Se muestran todos los términos.

A

Agilidad

Capacidad de adaptarse a cambios durante el desarrollo de software.

Algoritmo

Conjunto ordenado de pasos que permiten resolver un problema o realizar una tarea.

Análisis de requisitos

Proceso de identificar y comprender qué necesita el usuario del sistema.

Automatización de pruebas

Uso de herramientas y scripts para ejecutar pruebas de software automáticamente.

B

Backlog

Lista priorizada de funcionalidades, tareas o mejoras que el equipo puede desarrollar.

Bug

Error que provoca que un programa funcione de manera incorrecta.

C

Calidad de software

Grado en que un programa cumple los requisitos y satisface las necesidades de los usuarios.

Caso de prueba

Conjunto de condiciones, datos y pasos utilizados para comprobar una funcionalidad.

Ciclo de vida del software

Conjunto de etapas por las que pasa un producto desde la concepción hasta su mantenimiento.

Código fuente

Instrucciones escritas por desarrolladores mediante un lenguaje de programación.

D

Depuración

Proceso de encontrar, analizar y corregir errores en el código.

Desarrollo de software

Proceso de diseñar, construir, probar, entregar y mantener aplicaciones informáticas.

Diseño de software

Planificación de la estructura, los componentes y el comportamiento de un sistema.

E

Error

Equivocación humana que puede introducir un defecto y provocar un funcionamiento incorrecto.

Especificación

Descripción de los requisitos, las restricciones y las características que debe cumplir un sistema.

Estándar

Documento de referencia con criterios, requisitos o recomendaciones acordados para un ámbito determinado.

F

Framework

Estructura de herramientas, bibliotecas y convenciones que facilita la construcción de aplicaciones.

G

Gestión de calidad

Actividades coordinadas para planificar, controlar, asegurar y mejorar la calidad del software.

H

Historia de usuario

Descripción breve de una necesidad desde el punto de vista de quien utilizará el producto.

I

Incidencia

Situación detectada que requiere análisis, seguimiento o una acción correctiva.

Integración continua

Práctica de incorporar cambios al código frecuentemente y comprobarlos mediante pruebas automatizadas.

J

JavaScript

Lenguaje de programación utilizado para añadir comportamiento e interactividad a páginas web.

K

Kanban

Método visual para organizar tareas, limitar el trabajo en curso y observar el flujo de un equipo.

L

Lean Software Development

Enfoque que busca reducir actividades que no aportan valor y mejorar el flujo de entrega.

M

Mantenimiento

Modificación del software para corregir defectos, mejorar su funcionamiento o adaptarlo a nuevas necesidades.

Modelo XP

Extreme Programming, enfoque ágil que promueve programación en parejas, pruebas frecuentes y mejora continua.

N

Normalización

Proceso de organizar datos para reducir redundancias y mejorar su consistencia, especialmente en bases de datos.

O

Open Source

Software cuyo código fuente está disponible para consultar y, según su licencia, modificar y distribuir.

P

Prueba de software

Evaluación de un sistema para comprobar su comportamiento y detectar defectos.

Prueba de regresión

Prueba que verifica que los cambios recientes no hayan afectado funcionalidades existentes.

Q

QA (Quality Assurance)

Aseguramiento de la calidad mediante procesos y actividades dirigidos a prevenir problemas y mejorar el trabajo.

R

Requisito

Necesidad, capacidad o condición que un sistema debe cumplir.

Revisión de código

Examen del código por otra persona o mediante herramientas para detectar problemas y mejorar su claridad.

S

Scrum

Marco de trabajo que organiza el desarrollo en ciclos llamados sprints y promueve la inspección y adaptación.

Seguridad del software

Capacidad de proteger la información y el funcionamiento del sistema frente a amenazas y usos indebidos.

Software

Programas, datos y elementos relacionados que permiten a un sistema informático realizar tareas.

T

Testing

Actividad de probar un programa para comprobar su comportamiento y encontrar defectos.

Trazabilidad

Capacidad de relacionar requisitos con diseños, código, pruebas y resultados para seguir su cumplimiento.

U

Usabilidad

Grado en que las personas pueden utilizar un sistema con eficacia, eficiencia y satisfacción.

V

Validación

Comprobación de que el software satisface las necesidades y el uso esperado por las personas usuarias.

Verificación

Comprobación de que el producto cumple las especificaciones y requisitos establecidos.

Versión

Estado identificable de un software que corresponde a una entrega o conjunto de cambios.

W

Waterfall

Modelo de desarrollo secuencial en el que las etapas se realizan principalmente una después de otra.

X

XP (Extreme Programming)

Enfoque ágil que prioriza la calidad del código, la colaboración, las pruebas y las entregas frecuentes.

Y

YAGNI

Principio que propone no implementar una funcionalidad hasta que realmente sea necesaria.

Z

Zero-day

Vulnerabilidad que se conoce cuando todavía no existe una corrección ampliamente disponible o que puede explotarse antes de que haya un parche.
